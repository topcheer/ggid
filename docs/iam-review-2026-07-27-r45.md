## 3. 安全审查

### 3.1 Scope escalation 防护 — ✅ 安全

`filterSafeScopes` (oauth_service.go): 仅允许 `openid/profile/email/offline_access`。Admin scopes 从 user DB role keys 获取，不从客户端请求。防 scope escalation ✅。

### 3.2 Gateway max body size — ✅ 安全

- 默认 10MB 限制 (error_pages.go:190)
- Input validation 10MB (input_validation.go:50)
- WASM 16MB 内存限制 ✅

### 3.3 Password history — ⚠️ 轻微竞争条件

`credential_repo.go:103-110`: AddToHistory 和 GetHistory 是独立 SQL 操作，非事务性。理论上两个并发密码更改可能通过 history 检查。但实际风险极低（同一用户同时改密码的场景罕见）。

### 3.4 Redis 并发 — ✅ 安全

- state 验证使用 `GetDel` (原子获取+删除) ✅
- token revocation Redis SET + TTL ✅
