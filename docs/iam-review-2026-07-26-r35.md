| P1-6 | P1 | JWKS 在密钥旋转期间不返回旧密钥 — `GetJWKS()` 只返回当前 keyProvider 的公钥。旋转后旧 kid 的 JWT 无法验证（RotatingKeyProvider 有 grace period 但 JWKS 不暴露旧公钥）|

## 2. 竞品迁移成本

### 从 Keycloak 迁移 — 新增缺口

- `response_mode=form_post` 未支持 — Keycloak SPA 客户端常用 form_post 避免 token 泄露到 URL fragment
- `prompt=none` 未支持 — Keycloak 静默续约（iframe check session）依赖 prompt=none
- `login_hint` 未支持 — Keycloak SSO 传递用户提示

### 从 Auth0 迁移 — 新增缺口

- `prompt=login` 未支持 — Auth0 强制重新认证
- `max_age` 未支持 — Auth0 会话超时控制

### 从 Okta 迁移 — 新增缺口

- `response_mode` 未支持 — Okta 支持 form_post
- JWKS 旋转期间旧 key 不可发现 — Okta 在旋转期间返回多个 key

### 更新后的迁移成本

| 来源 | 成本 | 新增阻塞 |
|------|------|----------|
| Keycloak | 中（升高） | response_mode, prompt, login_hint |
| Auth0 | 中 | prompt, max_age |
| Okta | 中 | response_mode, JWKS 旋转 |
| Authentik | 低 | 无新增 |

### 8.1 OAuth authorize 端点安全

- Redirect URI: 精确匹配 ✅（`ValidateRedirectURI` 逐个比对，非前缀/通配）

### 8.2 SAML assertion 签名验证

- 签名: `saml.VerifySignedAssertion` — 仅验证 Assertion 签名，不验证 Response 签名 → P2-35 已记录
- InResponseTo: 拒绝 solicited response（端点设计为 unsolicited-only）⚠️ 限制了 SP-initiated SSO
- AudienceRestriction: 强制验证 ✅
- NotBefore/NotOnOrAfter: 签发时设置 NotBefore，但 ACS 端未验证传入 assertion 的时间窗口

| ID | 严重性 | 描述 |
|----|--------|------|
| P2-41 | P2 | SAML ACS 未验证 assertion NotBefore/NotOnOrAfter 时间窗口 — 过期 assertion 可被接受 |
| P2-42 | P2 | SAML assertion ID 无去重机制 — 同一 assertion 可被重放（OneTimeUse 未强制）|

### 8.3 WebAuthn attestation 验证

- Attestation 格式: 5 种已实现（fido-u2f/android-key/android-safetynet/tpm/apple/none）✅
- AAGUID: LookupAAGUID 支持 TouchID/WindowsHello/anonymous/unknown ✅
- Challenge: 返回给客户端但未见验证逻辑
- Trust anchor/root cert: 解析 attestation 证书但未见根证书链验证

| ID | 严重性 | 描述 |
|----|--------|------|
| P2-43 | P2 | WebAuthn challenge 验证逻辑未见 — challenge 存储和返回但未确认在 assertion 时验证 |
| P2-44 | P2 | WebAuthn attestation 未验证证书链根 CA（trust anchor）— 仅解析叶子证书 |

### 8.4 JWKS 多密钥共存

- `RotatingKeyProvider.PreviousPublicKey()` 方法存在，在 grace period 内返回旧公钥
- **但 `GetJWKS()` 只调用 `s.keyProvider.Public()`（当前密钥），不调用 `PreviousPublicKey()`**
- 旋转后客户端无法从 JWKS 获取旧 kid 的公钥 → P1-6 已记录，确认严重

### 8.5 OIDC end_session + replay 防护覆盖面

- End session: `ClientID` 字段标记 "optional"，未验证与 id_token_hint 的 aud 匹配
- State 参数: 原样返回 ✅
- Replay 防护覆盖面:
  - Authorization code: 原子 SQL `WHERE used = false` ✅
  - Refresh token: 旋转 + family reuse detection ✅
  - Device code: 消费后不可重用 ✅
  - SAML assertion ID: **无去重** → P2-42
  - Access token JTI: **无 replay 检查** → P2-36 已记录

| ID | 严重性 | 描述 |
|----|--------|------|
| P2-45 | P2 | OIDC end_session 未验证 RP client_id 与 id_token_hint audience 匹配 |

### 10.2 SAML assertion 签名验证深度

- **Signature**: `saml.VerifySignedAssertion(rawXML, trustCfg.Cert)` 验证 assertion 签名 ✅
- **Signature wrapping**: `ValidateSignature` 检查 `info.referencedID != "#"+assertion.ID` — 签名必须引用 assertion ID ✅
- **NotBefore/NotOnOrAfter**: `ValidateConditions()` **存在且正确实现**（2 分钟 clock skew tolerance）✅
- **但 ValidateConditions 未在 ACS handler 中调用** — ACS flow (server.go:1238-1271) 验证签名、InResponseTo、Issuer、Audience，但**从不调用 ValidateConditions()** → **P2-41 严重性应升级**

| P2-41→P1-8 | P1 | SAML ValidateConditions() 存在但未在 ACS handler 中调用 — 过期 assertion 可被接受（代码实现了时间验证但未接入流程）|

- **Assertion ID dedup**: 测试中有 `assertionIDCache` 但生产 ACS handler 无去重 → P2-42 确认
- **Issuer**: 验证匹配 trustCfg.IdPEntityID ✅
- **Audience**: 验证匹配 spEntityID ✅
- **InResponseTo**: 拒绝 solicited response（仅接受 unsolicited）✅

### 10.3 WebAuthn attestation 验证

- **Challenge**: 存储在 sessionStore，5 分钟 TTL，查找后删除（one-time use）✅
- **Challenge 验证**: 使用 go-webauthn 库 `h.wbn.CreateCredential(user, *sd.data, parsedResponse)` — 库内部验证 challenge ✅
- **Attestation formats**: 5 种格式实现 (fido-u2f/android-key/android-safetynet/tpm/apple/none) ✅
- **Root CA**: 自定义 `VerifyAttestationFormat` 解析叶子证书但未验证根 CA 链 → P2-44 确认

- rbac_dynamic.go:303: `for _, rn := range claims.Roles { userRoles[strings.ToLower(rn)] = true }` — roles claim 用于权限检查
- rbac_dynamic.go:338: `userRoles[strings.ToLower(row.RoleName)] || userRoles[strings.ToLower(row.RoleKey)]` — 按 name 和 key 匹配
