### 新发现的差距

| ID | 严重性 | 描述 |
|----|--------|------|
| P1-6 | P1 | JWKS 在密钥旋转期间不返回旧密钥 — `GetJWKS()` 只返回当前 keyProvider 的公钥。旋转后旧 kid 的 JWT 无法验证（RotatingKeyProvider 有 grace period 但 JWKS 不暴露旧公钥）|
| P1-7 | P1 | `post_logout_redirect_uri` 未验证是否为客户端注册的 URI — 代码注释明确说 "In production, validate against client's registered post_logout_redirect_uris"，目前只验证 URL 格式。开放重定向漏洞 |
| P2-31 | P2 | `response_mode` 参数未实现（OAuth 2.0 `query`/`fragment`/`form_post`）— Keycloak/Auth0/Okta 支持 |
| P2-32 | P2 | `prompt` 参数未实现（OIDC `none`/`login`/`consent`/`select_account`）— 影响静默续约和强制重认证 |
| P2-33 | P2 | `max_age` 参数未实现（OIDC §3.1.2.1 请求重新认证时间窗口）|
| P2-34 | P2 | authorize 端点不支持 `login_hint` 参数（仅 CIBA 支持）— Keycloak/Auth0 支持 |
| P2-35 | P2 | SAML ACS 仅验证 assertion 签名，未验证 Response 签名 — SAML wrapping 攻击风险（应同时验证 Response 和 Assertion 签名）|
| P2-36 | P2 | access token 无 JTI replay 保护 — 仅 logout token 有 JTI 检查。被盗的 access token 可在有效期内无限重放 |
| P2-37 | P2 | WebAuthn "none" attestation format 无条件接受 — 不验证设备认证状态（适合 passkey 但不适合高安全场景）|

## 2. 竞品迁移成本

### 从 Keycloak 迁移 — 新增缺口

- `response_mode=form_post` 未支持 — Keycloak SPA 客户端常用 form_post 避免 token 泄露到 URL fragment
- `prompt=none` 未支持 — Keycloak 静默续约（iframe check session）依赖 prompt=none
- `login_hint` 未支持 — Keycloak SSO 传递用户提示

### 从 Auth0 迁移 — 新增缺口

- `prompt=login` 未支持 — Auth0 强制重新认证
- `max_age` 未支持 — Auth0 会话超时控制

### 从 Okta 迁移 — 新增缺口

- `response_mode` 未支持 — Okta 支持 form_post
- JWKS 旋转期间旧 key 不可发现 — Okta 在旋转期间返回多个 key

### 更新后的迁移成本

| 来源 | 成本 | 新增阻塞 |
|------|------|----------|
| Keycloak | 中（升高） | response_mode, prompt, login_hint |
| Auth0 | 中 | prompt, max_age |
| Okta | 中 | response_mode, JWKS 旋转 |
| Authentik | 低 | 无新增 |

## 3. 安全审查

### 3.1 开放重定向

| ID | 严重性 | 描述 |
|----|--------|------|
| P1-7 | P1 | post_logout_redirect_uri 未验证是否为客户端注册 URI — 攻击者可构造任意重定向 URL |

### 3.2 SAML 签名验证

| ID | 严重性 | 描述 |
|----|--------|------|
| P2-35 | P2 | SAML ACS 只验证 assertion 签名，不验证 response 签名 — SAML wrapping 攻击：攻击者可伪造 Response 包装合法 Assertion |

### 3.3 Token 重放

| ID | 严重性 | 描述 |
|----|--------|------|
| P2-36 | P2 | access token 无 JTI replay 保护 — 仅有 logout token 的 JTI 检查。被盗的 access token 在过期前可无限重放 |

### 3.4 WebAuthn 安全

| ID | 严重性 | 描述 |
|----|--------|------|
| P2-37 | P2 | "none" attestation format 无条件接受 — 不验证设备来源，适合 passkey 但不适合要求设备认证的高安全场景 |

### 3.5 确认安全的领域

- Redirect URI 精确匹配（非前缀）✅
- PKCE 对 public client 强制 ✅
- Nonce 在 id_token 中返回 ✅
- Authorization code 原子消费 + 一次性使用 ✅
- Client binding for auth code (`code.ClientID != client.ID`) ✅
- redirect_uri 在 token 端点验证 ✅
- Introspection 强制 client auth ✅
- WebAuthn attestation 支持 5 种格式（fido-u2f/android-key/android-safetynet/tpm/apple）✅
